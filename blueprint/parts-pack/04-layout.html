Layering rules

  • api → service → model. A router never touches a provider, a model, or another service's tables.
  • services own tables. Cross-service reads go through a service function, not a join.
  • integrations are adapters. One file per provider exposing connect / refresh / health / operation. Provider ids never leave the adapter.
  • agent manifests are data. Adding a role is a YAML file plus a golden set — never a new class hierarchy.
  • workers import services, never the reverse. A service must be callable from an HTTP request in tests.
Two shortcuts worth taking

Keep the backend as one FastAPI process with logical modules — do not split services into separate deployments until a measured reason appears. And put the agent manifests on disk rather than in the database for PH-1/PH-2; move them into agents.config only when per-tenant override is actually needed.
