Backend conventions

  • One router per resource. Handlers do: parse → call service → shape response. No business logic in a handler.
  • Services are plain functions taking a session and explicit arguments. No global state, no class singletons.
  • Tenant context is set per transaction (SET LOCAL app.current_org), never per connection.
  • Errors are typed. Raise AppError(code, message, details); one handler renders the envelope in §6 of the blueprint.
  • Every write that matters emits an event after commit, not before.
  • No synchronous model calls in a request path. Enqueue, return 202.

Frontend conventions

  • Server components by default; client components only where interaction demands it.
  • One API client module with typed calls generated from the OpenAPI schema.
  • Never render a number the API did not return. No client-side metric maths.
  • Every cost is rendered with its source (ledger row, campaign, task).
  • Approval screens always show the exact payload and the action class.

Environment

Four variables are mandatory at boot or the app refuses to start: DATABASE_URL, REDIS_URL, OPENROUTER_API_KEY, TOKEN_ENCRYPTION_KEY. Fail loudly at startup — a missing key discovered at 02:00 during a send is the worst possible failure mode.
