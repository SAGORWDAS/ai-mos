The fourteen acceptance tests

These names must exist in the suite. Each one is a claim the system can survive a specific failure. Manually, before each phase exit: revoke the mailbox grant, exhaust the data quota mid-run, kill a worker mid-send, force model timeouts, corrupt an approval payload, set a budget to zero, deliver a webhook twice — each must fail closed, visibly, with no duplicate external effect.

Prompt templates

Three blocks to copy verbatim. They exist to keep a session small and to make an agent's stopping behaviour predictable.

A. Start a task

Implement {TASK_ID}.

Load only:
  - spec/tasks/{TASK_ID}.yaml
  - the two spec slices it names
  - the existing files it names

Rules:
  - one task, one commit; do not start another task
  - do not add files that are not listed; report a gap instead
  - every external effect through the tool gateway, idempotency key required
  - tenant scoping on every query, RLS is not optional
  - write the test named on the card before the implementation

Stop when done_when is true. Report: files changed, test output, any gap.

B. Report a specification gap

SPEC-GAP
task: {TASK_ID}
missing: {the table, column, endpoint, tool or schema that does not exist}
blocked: {what cannot be written without it}
proposed: {the smallest addition that would unblock it}
confidence: {how sure you are that this is genuinely absent, and not in another section}
