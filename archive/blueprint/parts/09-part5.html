Part 5

AI gateway and cost control

Model choice is a runtime decision made by policy and paid for out of a visible budget — not a string hardcoded in a prompt, and not a monthly invoice nobody can explain.

5.1 Why a gateway, not an SDK

Every model call in the system goes through one module. That module is small, boring and load-bearing.

ResponsibilityBehaviour
Provider abstractionOne normative call shape. Swapping a model or provider is a registry edit, never a code change.
RoutingSelects a tier from task class, impact, uncertainty and required output quality (§5.3).
Budget enforcementChecks org, workflow and task envelopes before dispatch, and fails closed.
LedgerWrites exactly one model_usage row per attempt, including failures and timeouts.
DeterminismPins model version, temperature and seed where the provider supports it, so a re-run is reproducible.
GuardsToken ceilings per call, refusal to send PII to a provider not approved for it.
FallbackOn provider failure, one retry at the fallback tier or an alternate provider; never silent degradation to a worse model without recording it.

Routing is resolved from four properties of the task. The agent's name is never an input.

def resolve_tier(task) -> Tier:
    if task.class in ALWAYS_T3:                 return T3
    score = 0
    score += 2 if task.impact == HIGH else 0
    score += 2 if task.uncertainty == HIGH else 0
    score += 1 if task.output_quality == CRITICAL else 0
    score += 1 if task.prior_attempts >= 1 else 0
    if task.value_usd_estimate > ESCALATION_VALUE_USD: score += 1
    tier = T2 if score >= 2 else T1
    if score >= 4: tier = T3
    return min(tier, task.agent.autonomy_model_ceiling)

The function is deliberately boring and unit-testable. It is also the only place where "which model" is decided — which means cost behaviour can be changed in one commit and evaluated against the ledger.

5.4 Budgets

Four envelopes, each enforced before dispatch, each owned by an organisation administrator.

EnvelopeScopeTypical limitOn breach
Per taskOne task instance$0.01 – $0.25Block task, mark blocked, notify; do not silently downgrade quality.
Per workflow runWKF-A … WKF-E$0.50 – $20Pause workflow, require a human decision to continue.
Per agent / dayAgent × organisation$1 – $25Agent stops accepting new tasks for the day.
Per organisation / monthTenantPlan-dependentRead-only mode; owner notified at 80% and 100%.

Three behaviours are non-negotiable. Budget checks happen before the call, using the estimated cost, not after using the actual. A breached budget never causes a partial external effect, because effects are the last step of a task. And every breach is an audit entry with the workflow, task and agent that caused it — so the conversation with the customer is about a specific campaign, not about a total.

Founder-stage defaults (normative, spec/ai-mos.spec.yaml#budgets): $0.02 per task, $0.50 per workflow run, $0.10 per agent per day, $2.00 per organisation per month. Normal use lands near $0.16 per month in inference; the ceiling exists to stop a runaway loop, not to authorise spending. See Part 12.5 for the arithmetic.

5.6 The cost ledger

model_usage
  id, organization_id, task_id, agent_id, campaign_id (nullable)
  request_id            -- provider correlation id, unique
  model_id, model_registry_version, tier
  input_tokens, output_tokens, cached_tokens
  latency_ms, status (ok | error | timeout | rejected)
  cost_usd              -- computed at write time from the price snapshot
  created_at

budgets
  id, organization_id, scope (org | agent | workflow | task_type)
  scope_ref, period (day | month), limit_usd, spent_usd, action_on_breach

Two derived views make cost legible without a data team: cost_per_task_type (p50/p95) and cost_per_outcome (inference + sending + data + review, divided by qualified leads or won customers). The second is the one that goes on the pricing page.

5.7 Model promotion

  1. A candidate model is registered with a price snapshot and no verified_at.
  2. The role's golden set runs against it (Part 4.6). Quality, latency and cost are recorded.
  3. It may be promoted only if it passes the role's threshold and costs less per passing task than the incumbent — or costs more and is a deliberate quality trade.
  4. Promotion is a registry edit with an approver and a date. Production never changes model automatically because a cheaper one appeared.
Why "cheapest that passes" is the correct rule

Model quality is not monotonic in price, and a task does not need a better answer than the business can act on. Matching the cheapest model that clears the role's measured threshold turns model selection from a religious argument into a spreadsheet.

5.8 Where the money actually goes

It is worth stating plainly, because the brief's headline cost figure invites the wrong conclusion: inference is unlikely to be the dominant cost of acquiring a customer.

Cost lineIllustrative scaleWhy it can dominate
Prospect dataper recordVolume × record price, before a single email is written.
Email infrastructureper mailbox, per monthDeliverability requires warmed domains, multiple mailboxes and often a dedicated sending platform.
Human approvalminutes × hourly rateDetermines your true CPL more often than token spend does.
Paid advertisingdiscretionaryCan exceed everything else combined if enabled carelessly.
Model inferencesub-cent per taskReal, controllable, and usually the smallest line at low volume.

The consequence for the build: cost instrumentation must cover all five lines, not just tokens. A dashboard that reports only inference spend will report a flattering cost per lead that is wrong by a factor of ten.
